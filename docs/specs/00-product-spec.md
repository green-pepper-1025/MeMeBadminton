# 00 Product Spec

## 一、产品定位

MemeBadminton 是一个 2D 横版羽毛球对打游戏，核心体验是两名玩家选择不同梗角色后进行实时对战。

游戏首先服务课程设计展示，因此优先级是：

1. 流程完整。
2. 对战能玩。
3. 联机链路清晰。
4. 技能和 UI 有最小表现。
5. 再考虑复杂同步、丰富动画和完整美术。

## 二、MVP 主流程

```text
启动游戏
  -> 主页面
  -> 点击“双人联机”
  -> 进入房间/匹配等待
  -> 双方进入角色选择
  -> 双方确认角色
  -> 进入对战场景
  -> 完成 11 分制、三局两胜比赛
  -> 展示结果
  -> 返回主页面或再来一局
```

## 三、MVP 必须包含

- 主页面。
- 双人联机入口。
- 房间等待状态。
- 双方角色选择。
- 对战场景初始化。
- 双人对打。
- 发球、击球、落地判分。
- 11 分制、三局两胜。

## 四、MVP 暂不包含

- 人机模式。
- 排位系统。
- 账号系统。
- 商业级反作弊。
- 服务器完整物理计算。
- 复杂断线恢复。
- 复杂角色养成。

## 五、角色设计原则

所有角色基础属性一致，差异来自：

- 外观。
- 技能。
- 技能表现。

这样可以避免早期数值平衡拖慢开发。

## 六、联机设计原则

MVP 的联机目标是“流程可演示”，不是商业级实时竞技。

后续服务端职责：

- 创建房间。
- 玩家加入房间。
- 同步玩家选角。
- 确认双方准备。
- 下发开局信息。
- 仲裁得分和关键事件。

客户端职责：

- 页面 UI。
- 本地输入。
- Cocos 物理。
- 对战表现。
- 角色技能表现。
