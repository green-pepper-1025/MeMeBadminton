#### TypeScript/JavaScript 命名规则

## 二、架构规范

### 2.1 模块通信规范

#### 禁止直接依赖

```typescript
// ❌ 错误：模块间直接依赖
class PlayerController {
    private _uiManager: UIManager;
    
    updateScore() {
        this._uiManager.showScore(10);  // 紧耦合
    }
}

// ✅ 正确：通过事件总线通信
class PlayerController {
    updateScore(score: number) {
        EventBus.emit(GameEvent.SCORE_CHANGED, { score });
    }
}

class UIManager {
    onLoad() {
        EventBus.on(GameEvent.SCORE_CHANGED, this.onScoreChanged, this);
    }
    
    onScoreChanged(data: { score: number }) {
        this.scoreLabel.string = data.score.toString();
    }
}
```

#### 单向数据流

```
数据层 (Data) → 逻辑层 (Logic) → 表现层 (Presentation)
     ↑                                      ↓
     └──────────── 事件反馈 ─────────────────┘
```

### 2.2 单一职责原则

```typescript
// ✅ 每个类只负责一个功能
class PhysicsManager {
    // 只负责物理计算
}

class RenderManager {
    // 只负责渲染
}

class AudioManager {
    // 只负责音效
}

// ❌ 避免"上帝类"
class GameManager {
    // 物理、渲染、音效、网络... 全部混在一起（不推荐）
}
```

### 2.3 依赖注入

```typescript

        private _inputHandler: InputHandler,
        private _physicsManager: PhysicsManager
    ) { }

// ✅ 通过配置注入

    constructor(config: SkillConfig) {
        this._config = config;
    }
```

### 4.1 单元测试

```typescript
// 测试文件命名：*.test.ts
// EventBus.test.ts

describe('EventBus', () => {
    let eventBus: EventBus;
    
    beforeEach(() => {
        eventBus = EventBus.getInstance();
        eventBus.clear();
    });
    
    it('should emit and receive events', () => {
        let received = false;
        eventBus.on('test:event', () => {
            received = true;
        });
        
        eventBus.emit('test:event');
        expect(received).toBe(true);
    });
    
    it('should unsubscribe events', () => {
        let count = 0;
        const callback = () => { count++; };
        
        eventBus.on('test:event', callback);
        eventBus.emit('test:event');
        
        eventBus.off('test:event', callback);
        eventBus.emit('test:event');
        
        expect(count).toBe(1);
    });
});
```

## 五、性能规范

### 5.1 避免频繁创建对象

```typescript
// ❌ 错误：每帧创建新对象
update(dt: number) {
    const velocity = new Vec2(this.vx, this.vy);  // 每帧创建
    this.position.add(velocity);
}

// ✅ 正确：复用对象
private _tempVec: Vec2 = new Vec2();

update(dt: number) {
    this._tempVec.set(this.vx, this.vy);
    this.position.add(this._tempVec);
}
```

### 5.2 对象池

```typescript
// ✅ 使用对象池管理频繁创建/销毁的对象
class ParticlePool {
    private _pool: Particle[] = [];
    
    get(): Particle {
        return this._pool.pop() || new Particle();
    }
    
    put(particle: Particle): void {
        particle.reset();
        this._pool.push(particle);
    }
}
```

### 5.3 避免过度计算

```typescript
// ❌ 错误：每帧计算不变的值
update(dt: number) {
    const maxSpeed = Math.sqrt(this.maxSpeedSquared);  // 每帧计算
    if (this.speed > maxSpeed) {
        this.speed = maxSpeed;
    }
}

// ✅ 正确：缓存计算结果
private _maxSpeed: number;

constructor() {
    this._maxSpeed = Math.sqrt(this.maxSpeedSquared);  // 只计算一次
}

update(dt: number) {
    if (this.speed > this._maxSpeed) {
        this.speed = this._maxSpeed;
    }
}
```

## 六、错误处理规范

### 6.1 统一错误处理

```typescript
// ✅ 使用 try-catch 捕获异常
try {
    const config = await ConfigManager.loadConfig('physics.json');
    this.applyConfig(config);
} catch (error) {
    Logger.error('Failed to load physics config', 'PhysicsManager', error as Error);
    EventBus.emit(GameEvent.ERROR_OCCURRED, { 
        module: 'PhysicsManager', 
        error 
    });
    // 使用默认配置
    this.applyDefaultConfig();
}
```

```typescript
// ✅ 参数校验
public setVelocity(velocity: Vec2): void {
    if (!velocity) {
        Logger.warn('Invalid velocity', 'Ball');
        return;

    if (isNaN(velocity.x) || isNaN(velocity.y)) {
        Logger.error('Velocity contains NaN', 'Ball');
        return;
```

## 十、总结

遵循本规范可以确保：
1. **代码一致性**: 团队成员编写风格统一的代码
2. **可维护性**: 代码易读、易理解、易修改
3. **可扩展性**: 架构清晰，易于添加新功能
4. **质量保证**: 通过测试和代码审查保证质量

**核心原则**:
- 简洁优于复杂
- 可读性优于技巧
- 一致性优于个性
- 实用性优于完美
