# 《抽象羽球大乱斗》简化服务器设计文档

> **项目定位**: 课程设计大作业，开发以简单为主  
> **核心原则**: 服务器只做关键判定，完整物理由客户端计算

---

## 一、简化设计理念

### 1.1 为什么简化？

**课程设计的时间和复杂度限制**:
- 完整的服务器端物理引擎需要大量开发和调试时间
- Go 和 Cocos Creator 的物理引擎对齐非常困难
- 对于 2 人对战的小规模游戏，客户端物理 + 服务器验证已足够

### 1.2 简化策略

```
完整服务器权威模型（复杂）:
服务器: 完整物理计算 + 碰撞检测 + 得分判定
客户端: 只负责渲染

简化模型（推荐）:
服务器: 关键事件判定（击球、得分、技能）
客户端: 完整物理计算 + 渲染
```

**权衡**:
- ✅ 开发时间大幅减少（省去服务器物理引擎）
- ✅ 客户端体验更流畅（无需等待服务器物理计算）
- ⚠️ 理论上可能被作弊（但课程设计不需要考虑）
- ⚠️ 客户端物理不一致时需要服务器仲裁

## 二、服务器职责划分

### 2.1 服务器负责的事情

| 职责 | 说明 | 实现难度 |
|------|------|----------|
| **连接管理** | WebSocket 连接、心跳、断线重连 | ⭐ 简单 |
| **房间管理** | 匹配玩家、创建房间、管理房间状态 | ⭐ 简单 |
| **输入转发** | 接收玩家输入，转发给对方客户端 | ⭐ 简单 |
| **击球判定** | 验证击球是否有效（防止作弊） | ⭐⭐ 中等 |
| **得分判定** | 判断球是否落地、出界、触网 | ⭐⭐ 中等 |
| **技能判定** | 验证技能使用条件，计算技能效果 | ⭐⭐⭐ 较难 |
| **比赛流程** | 管理回合、比分、发球权 | ⭐⭐ 中等 |

### 2.2 客户端负责的事情

| 职责 | 说明 |
|------|------|
| **完整物理计算** | 球的飞行轨迹、重力、阻尼、反弹 |
| **碰撞检测** | 球与地面、球网、玩家、球拍的碰撞 |
| **玩家控制** | 移动、跳跃、挥拍、球拍跟随鼠标 |
| **技能表现** | 技能动画、特效、慢动作、Cut-in |
| **UI 显示** | 计分板、技能条、得分提示 |

## 三、简化后的网络协议

### 3.1 核心消息类型（精简版）

```typescript
enum MessageType {
    // 连接（1x）
    HEARTBEAT       = 10,
    HEARTBEAT_ACK   = 11,
    
    // 匹配（2x）
    MATCH_JOIN      = 20,
    MATCH_FOUND     = 21,
    MATCH_START     = 22,
    
    // 输入转发（3x）
    PLAYER_INPUT    = 30,   // 客户端 → 服务器 → 对方客户端
    
    // 关键事件（4x）
    HIT_CONFIRMED   = 40,   // 服务器确认击球有效
    BALL_LANDED     = 41,   // 服务器判定球落地
    SKILL_ACTIVATED = 42,   // 服务器确认技能激活
    
    // 比赛状态（5x）
    SCORE_UPDATE    = 50,
    ROUND_END       = 51,
    MATCH_END       = 52,
}
```

### 3.2 输入转发机制

**核心思路**: 服务器只做"邮递员"，不做物理计算

```
客户端A                    服务器                   客户端B
    │                        │                        │
    │ [玩家按 S 键]          │                        │
    │ 立即计算击球结果        │                        │
    │ 立即更新球的速度        │                        │
    │                        │                        │
    │── PLAYER_INPUT ───────>│                        │
    │   {hit:true,           │                        │
    │    racketAngle:0.5,    │                        │
    │    ballVelocity:{...}} │ 验证击球合法性          │
    │                        │ (球在合理范围内)        │
    │                        │                        │
    │                        │── PLAYER_INPUT ─────────>│
    │                        │   (转发给B)             │
    │                        │                        │ 接收A的输入
    │                        │                        │ 更新本地球状态
    │                        │                        │
    │                        │ 判定球落地              │
    │<── SCORE_UPDATE ───────│── SCORE_UPDATE ─────────>│
```

**关键点**:
- 客户端 A 击球后，**立即**更新本地球的速度（不等服务器）
- 服务器接收到击球输入后，**转发**给客户端 B
- 客户端 B 接收后，更新本地球的状态（保持同步）
- 服务器只验证击球是否合法（防止明显作弊）

### 3.3 得分判定机制

**服务器监听客户端上报的球落地事件**:

```typescript
// 客户端检测到球落地
onBallLanded(position: Vec2): void {
    // 上报给服务器
    NetworkManager.send(MessageType.BALL_LANDED, {
        x: position.x,
        y: position.y,
        lastHitBy: this.ball.lastHitBy
    });
}

// 服务器判定得分
onBallLanded(data: BallLandedData): void {
    // 判断落在哪一侧
    const side = data.x < 0 ? 'left' : 'right';
    
    // 判断得分方
    const scoringPlayer = (side === 'left') ? 'player2' : 'player1';
    
    // 更新比分
    this.updateScore(scoringPlayer);
    
    // 广播得分
    this.broadcast(MessageType.SCORE_UPDATE, {
        scoringPlayer,
        player1Score: this.player1Score,
        player2Score: this.player2Score,
        reason: 'ball_landed'
    });
}
```

### 4.2 各技能的服务器端实现

#### 科比 - 直升机扣杀

```go
// server/internal/game/skill.go

func (s *SkillSystem) ExecuteHelicopterSmash(player *Player, ball *Ball) SkillResult {
    // 1. 计算瞬移位置（球的正上方 800px）
    teleportX := ball.X
    teleportY := ball.Y + 800
    
    // 2. 计算扣杀速度（垂直向下 2000px/s）
    ballVelocity := Vec2{X: 0, Y: -2000}
    
    // 3. 返回技能效果数据
    return SkillResult{
        SkillID: "helicopter_smash",
        PlayerPos: Vec2{X: teleportX, Y: teleportY},
        BallVelocity: ballVelocity,
        Duration: 1.0,  // 技能持续时间（秒）
    }
}
```

**客户端接收后**:
```typescript
onSkillActivated(data: SkillActivatedData): void {
    if (data.skillId === 'helicopter_smash') {
        // 1. 瞬移玩家
        this.player.setPosition(data.playerPos);
        
        // 2. 更新球速度
        this.ball.setVelocity(data.ballVelocity);
        
        // 3. 播放 Cut-in 动画
        CutInManager.show('kobe', 1.2);
        
        // 4. 慢动作效果
        Time.timeScale = 0.3;
        this.scheduleOnce(() => {
            Time.timeScale = 1.0;
        }, 1.2);
    }
}
```

    // 1. 计算曲线击球速度（添加随机偏移）

    curveOffset := Vec2{

**客户端接收后**:

onSkillActivated(data: SkillActivatedData): void {

            this.player.racketCollider.size.height /= data.sizeMultiplier;

### 5.2 房间核心逻辑（简化版）

```go
// internal/room/room.go

type Room struct {
    ID        string
    Player1   *hub.Client
    Player2   *hub.Client
    Match     *game.Match
    
    // 消息转发通道
    broadcast chan *proto.NetworkMessage
}

// 启动房间（消息转发循环）
func (r *Room) Start() {
    go func() {
        for {
            select {
            case msg := <-r.broadcast:
                r.handleMessage(msg)
            }
        }
    }()
}

// 处理消息
func (r *Room) handleMessage(msg *proto.NetworkMessage) {
    switch msg.Type {
    case proto.PLAYER_INPUT:
        // 转发给对方玩家
        r.forwardToOpponent(msg)
        
    case proto.BALL_LANDED:
        // 判定得分
        r.handleBallLanded(msg)
        
    case proto.SKILL_USE:
        // 处理技能
        r.handleSkillUse(msg)
    }
}

// 转发消息给对方
func (r *Room) forwardToOpponent(msg *proto.NetworkMessage) {
    // 判断发送者
    sender := r.getClientByID(msg.SenderID)
    
    // 转发给对方
    if sender == r.Player1 {
        r.Player2.Send(msg)
    } else {
        r.Player1.Send(msg)
    }
}

// 处理球落地
func (r *Room) handleBallLanded(msg *proto.NetworkMessage) {
    data := msg.Data.(proto.BallLandedData)
    
    // 判定得分方
    var scoringPlayer string
    if data.X < 0 {
        scoringPlayer = r.Player2.ID
    } else {
        scoringPlayer = r.Player1.ID
    }
    
    // 更新比分
    r.Match.AddScore(scoringPlayer)
    
    // 广播得分
    r.BroadcastAll(&proto.NetworkMessage{
        Type: proto.SCORE_UPDATE,
        Data: proto.ScoreUpdateData{
            ScoringPlayer: scoringPlayer,
            Player1Score:  r.Match.Player1Score,
            Player2Score:  r.Match.Player2Score,
            Reason:        "ball_landed",
        },
    })
}
```

## 六、开发优先级（MVP）

- [ ] WebSocket 服务器（连接、心跳）

## 七、与完整版的对比

| 功能 | 完整版（复杂） | 简化版（推荐） |
|------|---------------|---------------|

## 八、潜在问题与解决方案

### 8.1 客户端物理不一致

**问题**: 两个客户端的物理计算可能有微小差异

**解决方案**:
1. 使用相同的物理参数（从服务器下发配置）
2. 关键事件（击球、得分）由服务器仲裁
3. 定期同步关键状态（球的位置、速度）

### 8.2 作弊风险

**问题**: 客户端可以修改物理参数或伪造击球

**解决方案**:
1. 服务器验证击球合法性（球在合理范围内）
2. 服务器验证技能使用条件（充能、次数）
3. 课程设计不需要完美防作弊

### 8.3 网络延迟

**问题**: 输入转发有延迟，对方看到的动作会晚一些

**解决方案**:
1. 客户端预测（立即响应自己的输入）
2. 延迟补偿（根据 RTT 调整显示）
3. 100ms 以内的延迟基本感知不到

## 九、总结

**简化服务器设计的核心思想**:
1. **服务器是裁判，不是物理引擎** - 只判定关键事件，不计算完整物理
2. **客户端是运动员** - 自己计算物理，自己渲染画面
3. **输入转发 + 事件验证** - 服务器转发输入，验证关键事件

**适用场景**:
- ✅ 课程设计、毕业设计
- ✅ 小规模对战游戏（2-4人）
- ✅ 开发时间有限
- ❌ 商业游戏（需要完整防作弊）
- ❌ 大规模多人游戏

**开发建议**:
1. 先实现 MVP（基础联机 + 得分）
2. 再添加技能系统
3. 最后完善 UI 和特效
4. 保持代码简洁，不要过度设计
